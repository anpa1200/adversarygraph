# AdversaryGraph v8.1.0-beta.1 Release Notes

Source candidate date: 2026-09-22.

This minor beta increment packages the current deterministic PCAP investigation
and quality-remediation work. It retains the v8 Review Gate and durable-workflow
foundation. It is **not a stable release** or a claim of maximum analysis accuracy.
v7.0.0 remains the latest stable release.

## Changes

- Combined protocol decoding preserves packet/flow/identity provenance while
  reducing repeated capture scans; capture and semantic hashes remain distinct.
- Bounded inert recovery covers embedded base64 payloads, complete contiguous
  HTTP responses and IMF messages. SHA-256, SHA-1 and MD5 identify exported bytes;
  completeness and ambiguous request bindings remain explicit. No samples are executed.
- IOC assessment separates inventory, victim identities, recovered files,
  behavior-supported candidates and dated provider assertions. TLS cadence
  alone is not a maliciousness verdict; file reputation does not automatically
  make a hosting address malicious.
- Passive enrichment uses existing provider integrations, exact-target caches,
  shared cooldowns and per-provider pending status. Optional VirusTotal context
  failures do not erase a successful direct verdict. No payload uploads or active scans.
- Investigation handoff preserves malicious hash candidates and typed packet
  evidence. Full reports work without selected ATT&CK techniques; PDF byte-offset
  corrections preserve independently extractable text.
- Second-layer stories inherit governed source markings, require disclosure
  consent, use strict structured output and server-bound evidence passages, and
  retain source hashes, bounded retry diagnostics and provider-reported usage.
  Invalid drafts are not saved as validated stories. Bound quotes are not proof
  of semantic correctness or actor attribution.

## Recorded Validation and Limits

The implementation regression used the same ten previously reviewed public
training captures. These are **known cases, not a blind benchmark**. Its record:

| Measure | Result |
|---|---:|
| Comparable published payload hashes recovered | 12/12, previously 10/12 |
| Native full reports / text-parseable PDFs | 10/10 each |
| Exact expected identity strings | 22/24, previously 19/24 |
| Reference network values observed | 54/54 |
| Reference network values shortlisted | 20/54, previously 22/54 |
| Saved native stories in recorded attempts | 0/10 |
| Selected platform downloads independently hash/size checked | 21 |
| Original frozen files changed | 0/552 |

Decoder time was 80.974 seconds versus 119.667 seconds in single runs with
different profiles/load. This is not a controlled throughput benchmark. Known
shared-service noise was reduced, but shortlist recall fell; no overall accuracy
improvement or 100% precision claim is justified. Historical reputation drift,
provider gaps, encrypted content, bounded recovery and ambiguous identities remain.

The version-bumped source suite recorded 1,604 backend passes, 180 skips and
73.22% coverage; 35 decoder tests passed. The full local browser suite recorded
64 passes and four skipped release-screenshot tests. Frontend lint/build, version
consistency, module coverage, staged secret scanning and API contracts passed;
the generated API reference contains 360 operations across 31 modules and the
contract check covers 323 frontend calls. These are source checks, not the full
release-image scan or manual production acceptance gate.

The final passage-binding fix has local unit/integration and lossless
evidence checks; its live GPT-4.1 retest is pending explicit disclosure approval.
Oversized story requests also remain a provider-quota limitation. Qwen was not used.

See [implementation and regression notes](../pcap-quality-remediation-20260922.md).
Raw PCAPs, recovered payloads, local provider responses and screenshot bundles
are not included in this source commit. The regression scripts produce those
artifacts locally; external lookups still require explicit consent.

## Upgrade and Publication Boundary

Investigation marking adds `investigations.tlp` with a conservative default;
source restrictions remain authoritative. Existing evidence is not silently
declassified. Preserve database backups and follow the existing
[v8 readiness/migration checklist](../release-readiness-v8.md).

This commit/push is a source candidate, not an image publication or deployment.
The prior local regression images still identify as `8.0.0-beta.1`. New immutable
images and a GitHub pre-release exist only after a separately authorized,
successful protected `v8.1.0-beta.1` tag workflow with verified image digests.
Stable promotion and the remaining manual acceptance checks are separate decisions.
