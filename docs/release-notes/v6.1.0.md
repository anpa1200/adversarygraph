# AdversaryGraph v6.1.0 Unpublished Source Milestone

Release date: 2026-07-24

> **Superseded:** v6.1.0 was prepared as source metadata but was never published
> as an immutable stable tag or GitHub release. Its work is consolidated into
> [v6.5.0](v6.5.0.md). Do not use this page as proof of a published v6.1
> release or artifact.

This page preserves the scope of the v6.1 source milestone for historical
traceability.

## Added

- Persistent users-to-groups membership with twelve built-in SOC profiles:
  Platform Administrators, SOC Manager, SOC Tier 1/2/3, Threat Intelligence,
  Threat Hunting, Detection Engineering, Incident Response / DFIR,
  Vulnerability Management, Intelligence Feed Operators, and Audit / Read Only.
- Module-level authorization across 31 frontend workspaces and their backend
  APIs. Sidebar visibility, direct routes, and API calls use the same effective
  group policy.
- Administrative workflows for creating users and custom groups, assigning
  memberships, editing module/action grants, resetting passwords, managing MFA
  and sessions, and reviewing authentication audit events.
- Saved Threat Radar asset registry and asset detail pages with normalized
  inventory, alerts, assessment history, CVE candidates, ATT&CK techniques, and
  IOC relationships whose evidence origin is explicitly labelled.
- Inventory-bound exposure assessment using local intelligence plus configured
  VirusTotal, OTX, urlscan.io, GreyNoise, AbuseIPDB, Shodan, and Censys
  providers; optional bounded Nmap discovery; optional safe web posture checks;
  governed AI review; and controlled inventory merging of newly observed asset
  facts.
- Threat Hunting Query Library with reviewed and community-sourced Sigma,
  YARA-L, YARA, KQL, SPL, EQL, Lucene, SQL, osquery, and generic query
  workflows, including IOC-to-query generation and ATT&CK-linked search.
- Unified hybrid RAG, business-profile-aware retrieval, the governed Navigator
  assistant, and a bounded local stdio MCP interface.
- A detailed reference for all 31 governed modules, with prerequisites,
  step-by-step workflows, outputs, worked examples, illustrative case studies,
  limitations, and six cross-module case studies. CI verifies that every
  governed module remains documented exactly once.

## Security and Governance

- Group membership is persistent and audited. Grant ceilings prevent delegated
  administrators from assigning authority they do not possess.
- The final user-management principal cannot be disabled or stripped of either
  the Administration module or `manage_users` permission.
- Built-in group slugs are reserved, and only the system-owned Platform
  Administrators group can elevate an account to the administrator role.
- SOC Manager receives operational modules without platform configuration or
  identity administration. SOC Tier 1 receives the minimum triage,
  IOC-investigation, reporting, and escalation workspace.
- Asset assessment accepts only IP/domain/URL targets already present in the
  selected saved asset, blocks unsafe private-target provider egress, and
  requires explicit authorization for active discovery.
- AI, CVE, IOC, and service observations remain review leads rather than proof
  of exposure, exploitation, targeting, or compromise.

## Changed

- Backend, frontend, Helm, documentation, and version metadata now report
  v6.1.0. The Helm chart version is 0.3.0.
- API routers and frontend routes now enforce module access in addition to
  action permissions.
- Authentication documentation and the in-product guide now describe the SOC
  group model and least-privilege assignment workflow.
- The release line includes the post-v6 file/network hardening, session and MFA
  fixes, frontend resilience, immutable image workflow, and expanded automated
  API coverage recorded in the changelog.
- The current v6.1 source includes a user-creation UI hotfix: the action now
  remains available to explain invalid input, renders the active server
  password policy as an accessible checklist, reads browser/password-manager
  autofill from the submitted form, and blocks duplicate requests while the
  API call is pending.

## Validation

Before merge, the v6.1.0 source change set passed:

- 720 backend tests with 11 optional tests skipped;
- the 60% backend coverage gate, with 67.5% measured coverage;
- frontend lint and production build;
- ten Playwright authorization/browser tests, including the complete
  administrator user-creation flow;
- Ruff checks and patch-hygiene validation; and
- local Compose API/frontend health checks with all twelve SOC groups seeded.

The immutable release claim additionally requires merge CI and the tag workflow
to build, scan, publish, and verify the exact release images and digest
manifest.

## Upgrade Notes

1. Back up PostgreSQL and record the current container/image state.
2. Review `.env.example`, especially authentication, asset-scanner, provider,
   proxy, and network-egress settings.
3. Deploy the v6.1.0 source or immutable artifacts from the successful tag
   workflow.
4. Confirm all twelve access groups were seeded.
5. Create and test a Platform Administrator account before setting
   `AUTH_ENABLED=true`.
6. Assign users to least-privilege groups and test both visible navigation and
   direct API denial.
7. Run `./scripts/selftest.sh` and the documented release-readiness checks.

AdversaryGraph still performs additive startup schema compatibility rather than
using a formal Alembic migration chain. A verified backup is mandatory before
upgrading a production database.

## Boundaries

AdversaryGraph is a controlled self-hosted analyst workbench. It is not a
managed SaaS, a multi-tenant isolation boundary, an autonomous vulnerability
scanner, or a replacement for analyst validation and authorized scanning
processes.
