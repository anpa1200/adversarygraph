# AdversaryGraph v8.0.0-beta.1 Release Notes

Release date: 2026-08-25

AdversaryGraph v8.0.0-beta.1 is a manual-testing pre-release for governed
report promotion and durable research-workflow authority. It adds a five-gate,
two-person review boundary between report analysis and trusted downstream
intelligence, introduces a transactional workflow/outbox runtime backed by the
first four Alembic revisions, and moves Compose and Helm startup behind a
blocking schema-authority gate.

This version is **not the latest stable release**. v7.0.0 remains the latest
stable release while v8.0.0-beta.1 receives deployment-specific manual testing.
The beta must not be relabelled stable merely because source checks or automated
tests pass. Stable promotion requires the manual acceptance record in
[`release-readiness-v8.md`](../release-readiness-v8.md), a reviewed final diff,
and a separate stable release decision.

Immutable beta images, their digest manifest, and a GitHub pre-release exist
only if the protected `v8.0.0-beta.1` tag workflow completes successfully.
Source metadata, a branch name, or a local build is not publication evidence.

## Release Highlights

### Report Review Gate

- Report parsing, deterministic extraction, and optional AI assistance now
  produce candidates rather than authoritative intelligence.
- Every review revision is bound to the stored source and analysis fingerprints.
  Source or analysis changes make the current review stale and require a new
  revision.
- Deterministic preflight evaluates source provenance, publication date,
  procedure relevance, procedure-level claims, and actor identification.
  Machine output cannot set an analyst verdict.
- Claims are adjudicated independently as `suggested`, `accepted`, `rejected`,
  or `needs_evidence`; text evidence must bind to exact stored offsets and
  metadata evidence must bind to the acquisition receipt.
- Submission and approval are separate authorities. Approval requires a
  different authenticated human from the submitter, so meaningful beta testing
  requires `AUTH_ENABLED=true` and two named accounts.
- Promotion creates an immutable manifest. `canonical_intelligence` is
  mandatory; `rag`, `hunting`, and `exports` are explicit optional targets.
- Promotion and revocation history is append-only. Revocation or staleness
  withdraws active projections without erasing the decision history.

The Review Gate does not prove that a report is true, that its behavior occurred
in the local environment, or that an ATT&CK mapping is operationally detected.
It governs which source-bound claims are allowed to become trusted platform
inputs.

### Downstream evidence authority

- Report-derived graph nodes and edges require the exact current
  `canonical_intelligence` promotion and retain immutable promotion provenance.
- Report-derived IOC rows use a reserved promotion namespace and are revalidated
  against the live manifest on reads.
- RAG indexing requires both an active promotion and the `rag` target.
- Report-to-hypothesis generation requires an active promotion with the
  `hunting` target and revalidates authority before returning results.
- PDF and STIX/OpenCTI output remain non-authoritative or fail closed unless the
  active promotion includes the `exports` target.
- URL, upload, RSS, STIX/TAXII, MISP, OpenCTI, pipeline, and IOC report-intake
  paths preserve report candidates without bypassing the Review Gate.
- Generic IOC STIX/TAXII import rejects report-bearing bundles that would lose
  their report context.

These controls apply to report-derived intelligence. They do not make an
independent feed object, analyst observation, synthetic simulation, or external
SIEM result authoritative without its own documented evidence path.

### Durable research workflow runtime

- `/api/research/projects` stores project scope and immutable project revisions.
- Registered workflows persist runs, ordered stages, fenced attempts,
  checkpoints, cancellation identity, and terminal state.
- A transactional outbox separates database authority from broker delivery.
  Messages, delivery attempts, broker receipts, and workflow mutations are
  validated against detached, versioned lineage.
- Celery tasks publish due outbox rows, recover expired publisher/receipt leases,
  and recover expired stage executions in bounded batches.
- Worker heartbeat, checkpoint, completion, failure, cancellation, retry, and
  recovery paths use commit-owning coordinators and single-use transaction-local
  authority.
- The built-in `research.project.scope@1` stage is the only default workflow
  handler. Unknown stage types or versions fail closed.

The runtime is not a general arbitrary-job engine. New long-running handlers
must make external effects idempotent on stable lineage and renew their leases;
a handler that cannot replay safely must not be registered.

### Alembic and schema authority

The beta introduces a tested four-revision chain for the new authority domain:

1. `20260823_0001` creates research-project authority.
2. `20260823_0002` adds durable workflow, stage, and fenced-attempt records.
3. `20260823_0003` adds the transactional outbox, delivery attempts, and
   broker-receipt lineage.
4. `20260824_0004` applies the workflow contract, validates active lineage,
   serializes authority creation through canonical locks, and enforces terminal
   consistency.

API, worker, and Beat startup require the exact Alembic head and a
catalog-derived physical fingerprint for migration-owned tables. Docker Compose
runs a one-shot `migrate` service. Helm uses a first-install migration Job and a
blocking `pre-upgrade` hook, with schema-authority init containers on the
application workloads.

This is a hybrid migration period. Unrelated legacy tables still use additive
startup compatibility, and the beta does not claim complete Alembic ownership,
zero-downtime migration, or downgrade safety. Never use `alembic stamp` to skip
a failed contract preflight.

### Frontend and operator experience

- Reports / Research, AI Analysis, Linked Report, APT Library, and Operations
  expose the current review and workflow authority instead of presenting report
  extraction as trusted state.
- The Review Gate interface supports preflight, gate and claim decisions,
  coverage exceptions, submission, independent approval, promotion, revocation,
  and append-only history.
- The frontend moves to React Router 7. The beta lockfile must still pass the
  configured dependency audit at the exact release revision; that result is
  point-in-time evidence, not a permanent no-vulnerability claim.

### Scanner supply-chain remediation

- The Nuclei v3.11.0 builder now uses the immutable Go 1.26.7 Alpine image and
  explicitly pins `golang.org/x/mod` v0.40.0 and `golang.org/x/text` v0.41.0.
- The image build verifies the Go toolchain and both embedded module versions
  from the compiled Nuclei binary, preventing module-order drift from silently
  restoring the vulnerable graph.
- The rebuilt scanner image has zero fixable HIGH or CRITICAL findings under
  the release gate's configured `--ignore-unfixed` policy. This does not claim
  that the image has no vulnerabilities or no unfixed upstream advisories.

### Operation Desert Hydra workflow draft

The beta includes a new, separate publication draft that adapts the 31-step

## Upgrade and Beta Deployment

1. Record the existing tag, image digests, configuration, and current database
   revision.
2. Take a verified logical PostgreSQL backup and test the restore path in a
   separate environment.
3. Review the legacy report-projection inventory described in
   [`upgrade-guide.md`](../upgrade-guide.md); do not bulk-delete records based on
   provenance labels alone.
4. Drain API writers and stop Celery worker and Beat processing.
5. Apply `python -m alembic upgrade head` from the exact reviewed beta backend
   artifact. Docker Compose and Helm perform this as a blocking gate; direct
   deployments must run it explicitly.
6. If `20260824_0004` rejects stored workflow authority, preserve the failure,
   repair from retained broker/audit evidence under an approved procedure, and
   retry. Do not stamp past it.
7. Deploy only revision-matched components. For prebuilt deployment, use only
   digests from the successful beta tag workflow's
   `adversarygraph-images.env` attachment.
8. Verify `/api/ready`, the authenticated full self-test, schema authority,
   worker/Beat processing, and RAG reconciliation.
9. Complete the manual beta matrix below before considering a stable release.

A successful migration is not reversed by an application or Helm rollback.
Confirm old-image compatibility before relying on rollback, and keep the backup
available throughout evaluation.

## Required Manual Beta Tests

At minimum, retain evidence for:

- fresh Compose installation and upgrade from a backed-up v7 database;
- fresh Helm installation and `pre-upgrade` migration-hook behavior;
- exact-head and physical-fingerprint rejection after deliberate non-production
  schema drift;
- one report through preflight, claim adjudication, submit, independent approve,
  promote, stale-on-edit, re-review, and revoke;
- negative tests for same-user approval, stale `expected_version`, unbound
  evidence, overlap-only attribution, incomplete coverage, and missing optional
  promotion targets;
- withdrawal and restoration behavior for graph, IOC, RAG, hunting, PDF, and
  STIX/OpenCTI consumers;
- research project start, idempotent replay, cancellation replay/conflict,
  worker retry, lease expiry, outbox publication, and recovery after worker or
  broker interruption;
- browser navigation and deep links after the React Router 7 migration; and
- the Desert Hydra guide only with public or synthetic material in an authorized
  lab, preserving `partial`, `failed`, and `not_proven` outcomes honestly.

Record operator, timestamp, exact commit/tag, architecture, deployment mode,
test data, expected result, actual result, and linked logs/screenshots for every
manual case. No unchecked item may be described as passed.

## Automated Validation Boundary

Run the complete source gate against the exact beta revision:

```bash
./scripts/release-readiness.sh --full
```

The full gate must pass independently in merge CI and in the protected beta tag
workflow. A local quick gate, documentation parse, source unit suite, or
successful container startup is useful development evidence but does not
replace the complete gate, manual beta acceptance, registry digest verification,
or deployment-specific authenticated self-test.

## Known Boundaries

- v7.0.0 remains the latest stable release.
- Manual beta acceptance is pending at release preparation time.
- The Review Gate governs report-derived authority; it is not truth or
  attribution automation.
- Service accounts cannot make gate or claim decisions.
- Alembic owns the research/workflow/outbox authority domain, not every legacy
  table.
- The workflow runtime supports registered, replay-safe handlers only.
- The release remains a controlled, self-hosted, single-workspace platform, not
  a hard multi-tenant or managed-SaaS boundary.
- AI output, retrieval ranking, synthetic telemetry, generated detections, and
  source overlap remain review leads rather than proof.
