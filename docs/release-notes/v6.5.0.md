# AdversaryGraph v6.5.0 Release Notes

Release date: 2026-07-25

AdversaryGraph v6.5.0 is the governed intelligence, hunting, exposure
assessment, and SOC operations release. It is the first stable release line to
consolidate all product work developed after the immutable v6.0.0 tag. The
earlier v6.1.0 source milestone was not published as a stable GitHub release and
is superseded by v6.5.0.

The source tree, backend, frontend, Helm chart, API reference, and documentation
declare v6.5.0. Immutable images, their digest manifest, and the GitHub release
exist only after the protected tag workflow completes successfully.

## Release Highlights

### Governed Threat Hunting

- A hypothesis-driven workspace records plan and scope, ATT&CK mappings,
  telemetry requirements, query revisions, findings, disposition, outcome, and
  handoff without claiming that AdversaryGraph executed an external SIEM query.
- AI assistance is available at each hunt stage. Local and explicitly
  permitted cloud providers share one governed selection model with TLP/legal
  controls, request acknowledgement, bounded context, audit records, and
  mandatory analyst review.
- Completed Enterprise ATT&CK report/research sessions can produce
  citation-bound hypothesis drafts. Source coverage, ATT&CK IDs, and stale
  context are validated before a draft can be applied.
- The self-hosted Monaco editor supports Sigma, YARA-L 2.0 for Google SecOps
  UDM, YARA, KQL, SPL, EQL, Lucene, SQL, osquery, and generic query text.

### Query Library and Detection Engineering

- The Query Library provides reviewed examples, typed autocomplete, facets,
  provenance, parser state, normalized tags, ATT&CK links, and direct handoff
  into a hunt draft.
- Bounded Git-backed community ingestion supports SigmaHQ, Google SecOps
  community YARA-L, and Yara-Rules sources while preserving upstream URL,
  identifier, license context, and validation metadata.
- Deterministic IOC-to-query generation types and escapes values locally and
  carries destination-validation warnings for every supported output format.
- Generated or AI-assisted query text is never represented as executed,
  validated, or production-safe until an analyst tests it in the destination
  telemetry platform.

### Unified RAG, Navigator Assistant, and MCP

- A normalized corpus covers IOC, CVE, ATT&CK/ATLAS, actors, campaigns, reports,
  knowledge, Threat Radar, Threat Hunting, Evidence Graph, and sanitized asset
  records.
- Retrieval combines exact identifiers, PostgreSQL full-text search, optional
  pgvector cosine similarity, reciprocal-rank fusion, and bounded one-hop
  expansion over allowlisted stored relationships.
- Saved business profiles add private region, sector, technology, and
  crown-jewel context at request time without becoming globally searchable
  corpus documents.
- The Navigator assistant returns citation-bound answers and checksum-bound
  temporary technique proposals. Only explicit analyst Add/Replace confirmation
  can apply a verified proposal, and applying it does not save a named layer.
- The local stdio MCP server exposes bounded authenticated search, entity
  retrieval, grounded questions, and advisory Navigator proposals. It does not
  expose arbitrary SQL or URL fetching and cannot confirm a proposal, mutate a
  layer, reindex the corpus, or execute a response action.

### Threat Radar and Asset Exposure Assessment

- A searchable saved-asset registry exposes normalized inventory, alerts,
  assessment history, CVE candidates, ATT&CK techniques, and IOC relationships
  on a dedicated asset page.
- Exact asset/IOC identity, stored signal relationships, CPE candidates,
  product-name candidates, and scan-derived candidates carry distinct evidence
  labels. None is automatically treated as proof of exposure, exploitation,
  targeting, or compromise.
- Analysts can assess only an IP address or HTTP(S) target already stored on
  the selected asset. The workflow can combine configured passive OSINT,
  bounded unprivileged Nmap service discovery, safe web posture checks, local
  CVE candidates, and governed AI review.
- Active discovery requires explicit authorization and the relevant platform
  permission. Private-target provider egress is blocked, results are persisted
  and audited, and newly observed IP/domain/URL facts require a controlled
  inventory-merge action.

### SOC Users, Groups, and Module Authorization

- Persistent named users and access groups enforce both module visibility and
  action permissions in the frontend and backend API.
- Twelve built-in least-privilege profiles cover Platform Administrators, SOC
  Manager, SOC Tier 1/2/3, Threat Intelligence, Threat Hunting, Detection
  Engineering, Incident Response / DFIR, Vulnerability Management,
  Intelligence Feed Operators, and Audit / Read Only.
- Grant ceilings prevent delegated administrators from assigning authority they
  do not possess. The last user-management principal cannot be disabled or
  stripped of the Administration module or `manage_users`.
- The user-creation workflow now reads browser/password-manager autofill from
  the submitted form, prevents duplicate requests, and presents the current
  password policy and validation failures accessibly.

### Platform, API, and Release Hardening

- All 31 governed workspaces are covered by a code-validated module reference
  with inputs, workflows, outputs, examples, case studies, and limitations.
- The generated API reference covers 28 OpenAPI groups and validates backend
  contracts against frontend API usage. CI fails on undocumented or stale API
  contracts.
- Upload, archive, form, query, and provider-response limits are explicit.
  Outbound HTTP clients reject unsafe schemes, private/metadata destinations,
  unsafe redirects, environment proxies, and unbounded responses.
- Authentication, MFA enrolment, session administration, rate-limit identity,
  observability, error handling, task shutdown, and route authorization are
  hardened.
- Frontend startup, cancellation, stale-response suppression, deep links,
  error recovery, route splitting, safe URLs, and authenticated navigation are
  more resilient.
- The release path builds and scans seven versioned AdversaryGraph image
  families plus reviewed supporting images. It fails closed on artifact
  publication, tag provenance, digest verification, and tag protection.
- Source Compose builds remain local; production Compose and Helm require
  immutable release artifacts and deployment-specific reviewed digests.

## Upgrade Procedure

1. Back up PostgreSQL and record current container IDs, image digests, and
   deployment configuration.
2. Review `.env.example` for authentication, provider, RAG, asset scanner,
   proxy, and network-egress changes.
3. Run `./scripts/release-readiness.sh --full` against the exact source commit.
4. For prebuilt deployment, use only the seven immutable image digests attached
   by the successful v6.5.0 tag workflow. Do not substitute mutable tags.
5. Deploy the source build or verified artifacts.
6. Confirm all built-in access groups are seeded and a tested Platform
   Administrator exists before enabling authentication.
7. Assign least-privilege groups and test both visible route access and direct
   API denial.
8. Reconcile the RAG corpus and verify lexical-only or semantic readiness
   according to the deployment's configured embedding policy.
9. Run `./scripts/selftest.sh`, verify backup/restore procedures, and record
   acceptance evidence before promoting the deployment.

AdversaryGraph still uses additive startup schema compatibility rather than a
formal Alembic migration chain. A verified backup is mandatory before upgrading
an existing production database.

## Validation

The source release must pass the repository's repeatable release gate:

```bash
./scripts/release-readiness.sh --full
```

That gate checks release metadata, generated API contracts, patch hygiene,
ruleset-verifier tests, default/development/local-AI/production Compose
rendering, production environment policy, frontend lint/build/browser tests,
the Anomaly/ATLAS documentation build, backend lint/tests, dependency audits,
Bandit, Gitleaks, container builds, and strict image scans where the required
local tools and registry access are available.

Candidate validation executed on 2026-07-25 recorded:

- the canonical `./scripts/release-readiness.sh --full` gate completed
  successfully in one fail-closed run;
- 721 backend tests passed, 10 standalone MalwareGraph service tests skipped,
  67.53% line coverage, and the enforced 60% coverage floor passed;
- 53 browser tests passed and 4 opt-in screenshot capture tests were skipped;
- frontend lint and the production Vite build passed;
- API contract validation covered 28 OpenAPI groups, 322 operations, and 287
  frontend API call sites;
- documentation coverage validated all 31 governed workspaces exactly once;
- default, development, private local-AI, and production Compose renders
  passed, as did the production-environment policy;
- the Anomaly documentation production build, Helm lint, normal render,
  shared-storage render, and production render passed;
- Ruff, Bandit, `pip-audit`, the Anomaly docs dependency audit, Gitleaks, and
  release-tag ruleset verifier tests passed.
- The Anomaly documentation image's npm toolchain was pinned away from a
  bundled vulnerable `brace-expansion` 5.0.7 copy; its project dependencies and
  final image are scanned independently.
- The commit-pinned MalwareGraph UI build applies an integrity-pinned PostCSS
  8.5.18 lockfile patch and must pass `npm audit --audit-level=high` before
  compilation. The patch fails closed if the reviewed upstream lockfile
  context changes.
- The complete strict security gate rebuilt and scanned all seven custom image
  families plus the pinned Redis, BusyBox, and Nginx dependencies. It completed
  successfully with no fixable high- or critical-severity findings under the
  release policy.

The frontend audit retains two documented moderate React Router v6 advisories:
one affects SSR hydration, which this client-only frontend does not use, and
one concerns untrusted backslash navigation values. API-controlled external
links use the centralized safe-URL policy and unsafe-scheme browser tests.
Moving to Router 7 is deferred because its current dependency range introduces
a high React Server Components advisory and requires a breaking migration.
This is a reviewed residual risk, not a claim of a finding-free dependency
tree.

Passing a local source gate does not create immutable release evidence. Merge
CI and the protected v6.5.0 tag workflow must independently build, scan,
publish, and verify the exact release images and digest manifest.

## Boundaries

AdversaryGraph is a controlled self-hosted, single-workspace analyst workbench.
It is not a managed SaaS, a hard multi-tenant isolation boundary, an autonomous
vulnerability scanner, an attribution oracle, or a substitute for authorized
testing and analyst validation.

AI output, RAG ranking, relationship expansion, actor overlap, IOC/provider
matches, service discovery, CVE candidates, generated queries, synthetic
telemetry, and detection recommendations are review leads. They are not proof
of compromise, exploitation, applicability, attribution, or detection efficacy.
